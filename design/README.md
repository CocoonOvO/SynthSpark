# icespark 像素前端 · 设计样机与决议

> 本目录是 **icespark 分支**的新前端设计样机与决策记录。
> 样机已打通真实后端接口，用于确定视觉方向；方向定稿后再落为正式前端代码。

---

## 1. 核心命题

**站点不是「网站」，而是一台虚构的 8bit 掌机；用户不「浏览页面」，而是在「操作机器」。**

真正反传统的是三条，配色只是结果：

1. **场景取代页面** —— 没有纵向无限滚动，场景之间是整屏像素转场
2. **手柄优先，鼠标降级** —— 方向键移焦点、A 确认、B 返回
3. **没有 hover** —— 状态靠 8bit 闪烁选框表达，不靠悬停发光（最反 web 的一条）

## 2. 用户已确认的决议

| 决策项 | 结论 |
|--------|------|
| 屏幕模型 | **响应式像素网格**（不锁定固定虚拟分辨率，保留 8px 网格纪律） |
| 机身外壳 | **已移除** —— 画面即屏幕，全部空间让给内容与交互 |
| 导航模型 | **一屏一场景**：标签栏管浏览页，历史栈管前进/后退 |
| 交互底线 | **单独用鼠标、或单独用键盘，都能完成全部操作**（输入等价性） |
| 机器名 | **SYNTHSPARK** |
| 调色板 | **白底 + 浅蓝主体**（深色只作文字与细描边，禁止大面积铺底） |
| 开机流程 | 自检播完**自动进入主页**，无需等待输入（按任意键可跳过） |
| 视觉质感 | **8bit 显像管（CRT）**：扫描线 + 荫罩点阵 + 桶形暗角 + 荧光辉光 + 开机亮线 |
| 字体 | **真像素字体已接入并验证**（第 5 节）；像素字只用于结构性文字，正文走中文黑体 |
| 实现层级 | **皮肤式**：8bit 是外壳与交互，底层仍是正常文档（用户第四轮确认） |

### 第二轮修订记录（针对用户反馈）

| 反馈 | 处理 |
|------|------|
| 外壳多此一举 | 删除整个 `.rig` 机身条与状态栏装饰；屏幕铺满，仅保留底部一行极简场景指示 |
| 为什么是黑蓝色 | **根因**：深藏青 `--ink` 被当作边框色与选中底色满屏使用，加上 BOOT 整屏深色、卡片反白，视觉发黑。已重做调色板：`--ink` 降级为**纯文字/细描边用色**，选中态与分区一律改用浅蓝（`--blue-200` / `--blue-500`） |
| 像素字体没应用 | **根因**：样机从未引入真字体，用 JetBrains Mono 冒充。已接入 **Ark Pixel 12px**，`ArkPixel loaded` 已实测确认 |
| 开机需等待输入 | 自检播完 520ms 后**自动进入主页** |
| 需要 8bit 显像管质感 | 新增 `.crt` 三层质感（扫描线 / 荫罩点阵 / 暗角）+ `.crt-glow` 辉光 + `.crt-flicker` 刷新微抖 + `.crt-on` 开机亮线张开 |

本轮的结构性改动（不是加功能，是换骨架）：

- **`ui/scene.ts` 不再是历史栈，也不再拥有 `currentScene`**。它只剩两件事：把「当前路由」翻译成一个
  场景帧、做整屏像素转场。之所以不用 `<RouterView>`：像素转场要求「遮罩先盖上，内容 120ms 后再换」，
  而 RouterView 会在导航的同一帧就把组件换掉，遮罩来不及盖。
- **列表的浏览状态从内存搬进 URL**（`?group=&tag=&page=`）。因此「进文章 → 返回列表」能回到原页码，
  靠的不再是应用内状态，而是地址栏本身 —— 刷新、分享、新开窗口都成立。
- **`present()` 对同一帧不做转场**：列表换页 / 换筛选只是 query 变化，屏幕不动、焦点不丢，
  只有真正换场景（进文章、切标签页）才走转场。

本轮另外补的三件事：

- **场景栈升级为真正的历史栈**（`history` + `cursor`），否则「返回上一页 / 转到下一页」这两行没东西可接。
- **键盘焦点自动滚进视野**（`pad.ts` 的 `ensureFocusedVisible`）：焦点是我们自己用 class 画的，不是 DOM 焦点，
  浏览器不会帮我们滚动，页面一长键盘用户就会「焦点跑到屏幕外」。
- **样张数据源开关 `?demo=1`**：真实库里可能是重复标题、没有封面图的测试数据，而设计评审要看的恰恰是
  「有封面 / 无封面混排」这类形态。默认永远优先真接口。
- **`?demo=1` 会被列表导航保留**（`goPosts` 只重写 `group` / `tag` / `page`），否则在列表里一翻页
  样张模式就掉了，刷新即变回真数据源。

### 第七轮修订记录（本轮：用户 1 条，中间返工两次）

| # | 用户反馈 | 处理 | 落点 |
|---|----------|------|------|
| 1 | 「空画框依然太丑了。没有封面的文章需要无画框，用不同的布局方式在卡片中展示而不空旷」 | 结论：**无封面就不该占着图片位**。空画框在语义上是对的（「这里本来是图」），但视觉上仍然是一个空的图片槽 —— 只要它还在，卡片就永远是「少了一半」。这轮把「有 / 无封面」做成**两套排版**：有封面卡照旧左图右文；无封面卡**一张图的位置都不留**，改用文字卡（列表页：正文栏收窄 + 标题放大到 24px + 右侧立一条与卡片等高的「数据脊」；首页小卡：顶部横一条「分组 / 日期」头 + 正文撑满）。两套排版外框同高，同一行里依旧齐平 | `ui/ImageFrame.vue`、`ui/cover.ts`、`scenes/ArticleListScene.vue`、`scenes/HomeScene.vue`、`scenes/ArticleScene.vue`、`styles/pixel.css` |

返工过程（两条弯路都记在 `ui/ImageFrame.vue` 顶部，避免下次再撞）：

1. **抖动马赛克块**（第 6 轮被否）—— 与真封面同尺寸但质感完全不同，看起来像图挂了。
2. **空画框记号**（第 6 轮交付、第 7 轮被否）—— 外框 + 方块太阳 + 地平线，全方块、无圆角、纯蓝色阶，
   语义清楚、风格统一，但**它仍然是一个空的图片位**：卡片照样「上半张空着」。用户否的正是这一点。
3. **放大标题首字做水印**（更早试过）—— `ArkPixel` 是按 12px 设计的点阵字体，放大到 94px 后笔画被拉开、

顺带修掉的一个隐患：**「有没有封面」不能只看 `cover_image` 是否为空**。上传文件 404 时字段是满的、图是空的，
只看字段就会渲染出一个坏图框。这轮把判断收进 `ui/cover.ts`（`coverOk()` + `markCoverFailed()`），
列表页 / 首页 / 文章页三处共用同一套口径，同一条数据不会在不同页面上变成两种形态。

## 5. 字体：实测数据与建议

实测「方舟像素字体 Ark Pixel」发布包（woff2）：

| 方案 | 体积 | 汉字覆盖 | 结论 |
|------|------|----------|------|
| 12px 全量 | **738 KB** | 18,299 字 | 偏重 |
| 12px ⊂ 一级字表 3,755 字 | **123 KB** | 日常排版足够 | **推荐** |
| 12px ⊂ GB2312 全量 6,763 字 | **204 KB** | 几乎不缺字 | 稳妥选项 |
| 10px 全量 | 69 KB | **仅 1,076 字** | **已否决** |

**10px 为什么不选**：抽检 34 个常用字，「冰芯花 / 选择 / 评论 / 点赞 / 搜索 / 浏览」等 **17 个字直接缺失**，无法承担通用中文界面。

**关于「是否给其他机器带来负担」**：不会，但有前提 ——
- 字体是静态资源 + 强缓存，首次访问付一次代价，之后命中缓存；`font-display: swap` 不阻塞渲染
- 子集后 123 KB，比常见网页配图还小；对比思源黑体 Web 版动辄 1–2 MB，**像素字体反而更省**
- 可选进阶：按 A/B/C 分片，首屏仅约 30 KB

**已接入**：样机现在真的在用 Ark Pixel 12px（`public/fonts/ark-pixel-12px-zh-hans.woff2`），
实测 `document.fonts` 返回 `ArkPixel loaded`。字号严格锁定 12 的倍数（12/24/36/48/72），
并禁用抗锯齿 —— 非整数倍字号会让点阵糊成灰边。

**双层字体策略**（同时解决正文可读性）：
- **像素层**：全站 UI／标题／状态栏／对话框 → 方舟像素 12px 子集
- **阅读层**：正文段落 → 思源黑体，字号放大、关抖动（样机里已实现为「对比度旋钮」切换）
