# icespark 像素前端 · 设计样机与决议

> 本目录是 **icespark 分支**的新前端设计样机与决策记录。
> 样机已打通真实后端接口，用于确定视觉方向；方向定稿后再落为正式前端代码。

---

## 1. 核心命题

**站点不是「网站」，而是一台虚构的 8bit 掌机；用户不「浏览页面」，而是在「操作机器」。**

真正反传统的是三条，配色只是结果：

1. **场景取代页面** —— 没有纵向无限滚动，场景之间是整屏像素转场
2. **手柄优先，鼠标降级** —— 方向键移焦点、A 确认、B 返回
3. **没有 hover** —— 状态靠 8bit 闪烁选框表达，不靠悬停发光（最反 web 的一条）

## 2. 用户已确认的决议

| 决策项 | 结论 |
|--------|------|
| 屏幕模型 | **响应式像素网格**（不锁定固定虚拟分辨率，保留 8px 网格纪律） |
| 机身外壳 | **已移除** —— 画面即屏幕，全部空间让给内容与交互 |
| 导航模型 | **场景切换（一屏一场景）** |
| 机器名 | **SYNTHSPARK** |
| 调色板 | **白底 + 浅蓝主体**（深色只作文字与细描边，禁止大面积铺底） |
| 开机流程 | 自检播完**自动进入主页**，无需等待输入（按任意键可跳过） |
| 视觉质感 | **8bit 显像管（CRT）**：扫描线 + 荫罩点阵 + 桶形暗角 + 荧光辉光 + 开机亮线 |
| 字体 | **真像素字体已接入并验证**（第 5 节），正文可切阅读层 |

### 第二轮修订记录（针对用户反馈）

| 反馈 | 处理 |
|------|------|
| 外壳多此一举 | 删除整个 `.rig` 机身条与状态栏装饰；屏幕铺满，仅保留底部一行极简场景指示 |
| 为什么是黑蓝色 | **根因**：深藏青 `--ink` 被当作边框色与选中底色满屏使用，加上 BOOT 整屏深色、卡片反白，视觉发黑。已重做调色板：`--ink` 降级为**纯文字/细描边用色**，选中态与分区一律改用浅蓝（`--blue-200` / `--blue-500`） |
| 像素字体没应用 | **根因**：样机从未引入真字体，用 JetBrains Mono 冒充。已接入 **Ark Pixel 12px**，`ArkPixel loaded` 已实测确认 |
| 开机需等待输入 | 自检播完 520ms 后**自动进入主页** |
| 需要 8bit 显像管质感 | 新增 `.crt` 三层质感（扫描线 / 荫罩点阵 / 暗角）+ `.crt-glow` 辉光 + `.crt-flicker` 刷新微抖 + `.crt-on` 开机亮线张开 |

## 3. 样机结构

```
design/icespark-prototype/
├── public/fonts/             # Ark Pixel 12px 像素字体（gitignored，约 738KB）
├── src/styles/tokens.ts      # 唯一调色板（白底浅蓝）+ 场景定义
├── src/styles/pixel.css      # 像素铁律 + CRT 显像管质感
├── src/ui/pad.ts             # 手柄输入层（方向键/A/B）+ 打字机 + 计数滚动
├── src/ui/scene.ts           # 场景栈 + 整屏像素转场
├── src/ui/PixelAvatar.vue    # 头像降采样 + 色彩量化 → 统一成「机器居民」
├── src/ui/PixelDialog.vue    # RPG 对话框（全站唯一的输入/提示形态）
├── src/scenes/BootScene.vue  # 开机自检（BIOS → LOADING → 自动进主页）
├── src/scenes/TitleScene.vue # 主菜单（8bit 选项板，含锁定项）
├── src/scenes/WorldScene.vue # 文章列表（WORLD 1-1，关卡卡 + 分页）
└── src/scenes/StageScene.vue # 文章详情（关卡牌开场 + 双分辨率 + 加心）
```

跑起来：

```bash
cd design/icespark-prototype && npm install && npm run dev
# 代理已指向 http://localhost:8002（真实后端），连不上自动回退演示数据
```

操作：`↑↓←→` 移动　`A/Enter/Z` 确认　`B/Esc/X` 返回　右上角 `A`/`B` 按钮切调色板。

## 4. 调色板：白底 + 浅蓝主体

```dsh-ui 之外的纯文本说明（此处为文档）

| 角色 | 色值 | 用途 |
|------|------|------|
| `--paper` | `#FFFFFF` | 主背景（白） |
| `--paper-alt` | `#EAF6FC` | 次背景（极浅蓝分区） |
| `--blue-200` | `#D6ECF8` | 选中底色 / 浅蓝块 |
| `--blue-300` | `#A8D8EF` | 分隔线 |
| `--blue-400` | `#6FBCE0` | 卡片描边 |
| `--blue-500` | `#3D9BD0` | 主强调色（焦点框、进度条） |
| `--ink` | `#123A52` | **文字与细描边专用**（深蓝，不作大面积底色） |
| `--ink-soft` | `#5B8CA6` | 次要文字 |
| `--spark` | `#FF5C8A` | 点赞（克制使用） |
| `--coin` | `#FFC93C` | 成就 |

**关键纪律**：深色只用于文字与 1–3px 细描边；任何面积超过一小块的区域都必须走浅蓝或白。
上一版正是违反了这条（`--ink` 被当底色用），才让画面"发黑发蓝"。

## 5. 字体：实测数据与建议

实测「方舟像素字体 Ark Pixel」发布包（woff2）：

| 方案 | 体积 | 汉字覆盖 | 结论 |
|------|------|----------|------|
| 12px 全量 | **738 KB** | 18,299 字 | 偏重 |
| 12px ⊂ 一级字表 3,755 字 | **123 KB** | 日常排版足够 | **推荐** |
| 12px ⊂ GB2312 全量 6,763 字 | **204 KB** | 几乎不缺字 | 稳妥选项 |
| 10px 全量 | 69 KB | **仅 1,076 字** | **已否决** |

**10px 为什么不选**：抽检 34 个常用字，「冰芯花 / 选择 / 评论 / 点赞 / 搜索 / 浏览」等 **17 个字直接缺失**，无法承担通用中文界面。

**关于「是否给其他机器带来负担」**：不会，但有前提 ——
- 字体是静态资源 + 强缓存，首次访问付一次代价，之后命中缓存；`font-display: swap` 不阻塞渲染
- 子集后 123 KB，比常见网页配图还小；对比思源黑体 Web 版动辄 1–2 MB，**像素字体反而更省**
- 可选进阶：按 A/B/C 分片，首屏仅约 30 KB

**已接入**：样机现在真的在用 Ark Pixel 12px（`public/fonts/ark-pixel-12px-zh-hans.woff2`），
实测 `document.fonts` 返回 `ArkPixel loaded`。字号严格锁定 12 的倍数（12/24/36/48/72），
并禁用抗锯齿 —— 非整数倍字号会让点阵糊成灰边。

**双层字体策略**（同时解决正文可读性）：
- **像素层**：全站 UI／标题／状态栏／对话框 → 方舟像素 12px 子集
- **阅读层**：正文段落 → 思源黑体，字号放大、关抖动（样机里已实现为「对比度旋钮」切换）

## 6. 已实现的反传统交互清单

| 机制 | 实现位置 | 说明 |
|------|----------|------|
| 场景栈 + 整屏转场 | `ui/scene.ts` | 闪白 / 竖条擦除 / 抖屏，取代路由跳转 |
| 转场不吞输入 | `ui/scene.ts` | 转场可被打断；同一目标连点只算一次，换目标则立刻结算上一次（不做输入排队） |
| 手柄输入 | `ui/pad.ts` | 方向键/WASD、A=确认、B=返回、**P=START**；输入框内不劫持按键 |
| 消费语义 | `ui/pad.ts` | 事件处理返回布尔值，**只有被消费才 preventDefault**，没接管的按键还给浏览器 |
| 共享焦点 | `ui/focus.ts` | 键盘与鼠标共用同一个焦点；键盘移动出声，鼠标划过静音（避免滑动时噪音轰炸） |
| START 暂停菜单 | `ui/PauseMenu.vue` | 全局导航 + 全局设置的唯一入口，任何场景下 P / Esc / 点软按键都能呼出 |
| 信号档 | `ui/prefs.ts` | 一个旋钮同时管 CRT 强度、字体层、动效强度（0 纯净 / 1 阅读 / 2 标准 / 3 原教旨） |
| 8bit 音效 | `ui/sfx.ts` | WebAudio 方波实时合成，**零音频资源**；默认静音，首次交互时询问 |
| 闪烁选框焦点 | `pixel.css` `.focusable` | 左右各一块闪烁实心方块，无发光描边 |
| 头像像素化 | `ui/PixelAvatar.vue` | canvas 降采样 + 量化到本站调色板，跨域失败回退到名字哈希生成图案 |
| RPG 对话框 | `ui/PixelDialog.vue` | 逐字出字、▼ 闪烁提示、A 推进 / B 关闭 |
| 关卡牌开场 | `StageScene.vue` | 进入文章先出 STAGE 牌，逐步出字后自动进场 |
| 加心 | `StageScene.vue` | 点赞 = 8bit 心形跳动 + SCORE 计分，非现代点赞按钮 |
| 离散动画 | `pixel.css` | 全局 `steps()`，时长只有 80/160/320ms |
| 抖动图案 | `pixel.css` `.dither-*` | 像素世界唯一的「渐变」表达 |
| 8bit 立体边框 | `pixel.css` `.bevel` | 左上高光 1px / 右下暗影 1px |

## 7. 验证结论（已用无头浏览器实测）

### 第三轮：输入等价性 + 配色门（本轮）

输入等价性是用户提出的硬指标，已写成可执行用例 `design/icespark-prototype/e2e/parity.mjs`
（`node e2e/parity.mjs`，需要 5173 的 dev server）。**当前 69 项断言全部通过。**

| 用例组 | 覆盖内容 |
|--------|----------|
| 路线 A 纯键盘 | 全程不碰鼠标：焦点移动 → P 呼出菜单 → 信号/音效调节 → 进列表 → 进文章 → 滚动正文 → 动作栏加心 / 评论 / 返回 → 翻页 → 回主菜单 |
| 路线 B 纯鼠标 | 全程不碰键盘：划过即共享焦点 → 点进列表/文章 → 加心 / 评论 / 关闭对话框 / 返回列表 → 翻页 → 点软按键开 START 菜单 → 点分段调信号与音效 |
| 信号联动 | 信号 0 → 正文走阅读层；信号 3 → 像素层 + 开启 CRT 刷新微抖 |
| 无障碍 | `prefers-reduced-motion` 下**零动画在跑**，且键盘交互全部保留 |
| 配色门 | 枚举样式表里**所有** `var()`（16 个）逐个断言能取到值，并断言屏幕/卡片边框真的画出来了、焦点选框在像素级别真的可见 |

### 本轮修掉的真实缺陷

| # | 缺陷 | 根因 | 修法 |
|---|------|------|------|
| 1 | **全站配色从未生效** | `tokens.ts` 定义了 19 个 CSS 变量，但**没有任何地方注入**；CSS 里却有 220 处 `var()` 引用。取不到值时整条声明按「计算值无效」处理：背景变透明、`border` 简写被重置为 `none`。结果不是「颜色偏了」，而是**边框全部消失、只剩白底黑字** | `main.ts` 注入 `ROLES`；新增「配色门」用例：枚举所有 `var()` 断言可解析 |
| 2 | 文章页方向键滚不动正文 | 输入层全局 `preventDefault` 了方向键，但文章页没有接管 | 引入消费语义 + `scrollScreenBy()`，滚不动时才把按键还给浏览器 |
| 3 | 文章页 Enter 误触「加心」 | 动作栏焦点默认停在第一项 | 焦点初始 `-1`（未接管），先按 `→` 进动作栏，Enter 才有动作 |
| 4 | 鼠标无法返回列表 | 返回只有一行键盘提示文字，没有实体控件 | 动作栏加「◀ 返回列表」按钮 |
| 5 | 转场期间吞掉点击 | `pushScene` 在 `isTransitioning` 期间直接 return | 转场可打断 + 同目标去重；内容一换完立刻解锁输入 |
| 6 | 对话框 Esc 无响应 | 组件 emit `close` 但父级只监听了 `done` | 补 `@close`；并加「✕ 关闭」实体键供鼠标路径 |
| 7 | 对话框背后正文跟着滚 | 对话框没有模态化按键 | 对话框内消费全部方向键 |

> 教训记录：上一轮报告里「配色视觉核验通过」是**错的**。当时只看了截图、没量实际计算值，
> 而缺变量导致的「白底黑字无边框」被误读成了「1-bit 像素风」。本轮起，凡是色彩/视觉结论
> 都必须有计算样式或像素级断言兜底。

### 样机阶段发现、正式开发需处理的问题

1. **正文是 Markdown 原文未渲染** —— 正式开发必须接 `MarkdownRenderer`（样机为纯文本直出）
2. `likes.getLikers` 等旧封装路径错误，见 `frontend/API-SURFACE.md` 第 14 节
3. 头像量化依赖 canvas 读像素，跨域图会回退；正式版需后端支持同源或 CORS
4. 场景切换目前不改变 URL，**正式版需解决深链接与 SEO**（建议场景 ↔ URL 双向映射）
5. 像素字体为 738KB 全量版本，正式版应子集化到 **123KB**（见第 5 节）
