# icespark 像素前端 · 设计样机与决议

> 本目录是 **icespark 分支**的新前端设计样机与决策记录。
> 样机已打通真实后端接口，用于确定视觉方向；方向定稿后再落为正式前端代码。

---

## 1. 核心命题

**站点不是「网站」，而是一台虚构的 8bit 掌机；用户不「浏览页面」，而是在「操作机器」。**

真正反传统的是三条，配色只是结果：

1. **场景取代页面** —— 没有纵向无限滚动，场景之间是整屏像素转场
2. **手柄优先，鼠标降级** —— 方向键移焦点、A 确认、B 返回
3. **没有 hover** —— 状态靠 8bit 闪烁选框表达，不靠悬停发光（最反 web 的一条）

## 2. 用户已确认的决议

| 决策项 | 结论 |
|--------|------|
| 屏幕模型 | **响应式像素网格**（不锁定固定虚拟分辨率，保留 8px 网格纪律） |
| 机身外壳 | **不做**，重点突出内容与交互感 |
| 导航模型 | **场景切换（一屏一场景）** |
| 机器名 | **SYNTHSPARK**（丝印 `MODEL SYNTHSPARK-01`） |
| 字体 | UI/标题走像素字体，正文可切阅读层（见第 5 节实测数据） |
| 调色板 | **待定** —— 样机支持 A/B 实时切换，等你看图后拍板 |

## 3. 样机结构

```
design/icespark-prototype/
├── src/styles/tokens.ts      # 两版调色板 + 场景定义
├── src/styles/pixel.css      # 像素设计铁律（圆角0/无模糊阴影/无渐变/steps动画）
├── src/ui/pad.ts             # 手柄输入层（方向键/A/B）+ 打字机 + 计数滚动
├── src/ui/scene.ts           # 场景栈 + 整屏像素转场
├── src/ui/PixelAvatar.vue    # 头像降采样 + 色彩量化 → 统一成「机器居民」
├── src/ui/PixelDialog.vue    # RPG 对话框（全站唯一的输入/提示形态）
├── src/scenes/BootScene.vue  # 开机自检（BIOS → LOADING → PRESS START）
├── src/scenes/TitleScene.vue # 主菜单（8bit 选项板，含锁定项）
├── src/scenes/WorldScene.vue # 文章列表（WORLD 1-1，关卡卡 + 分页）
└── src/scenes/StageScene.vue # 文章详情（关卡牌开场 + 双分辨率 + 加心）
```

跑起来：

```bash
cd design/icespark-prototype && npm install && npm run dev
# 代理已指向 http://localhost:8002（真实后端），连不上自动回退演示数据
```

操作：`↑↓←→` 移动　`A/Enter/Z` 确认　`B/Esc/X` 返回　右上角 `A`/`B` 按钮切调色板。

## 4. 两版调色板（待选）

| | 方案 A · 纯单色 | 方案 B · 火花强调 |
|---|---|---|
| 灵感 | Game Boy | NES |
| 色阶 | 冰蓝 4 阶 | 冰蓝 8 阶 + 强调色 |
| 强调色 | **无** | `#FF4D6D` 火花（点赞/成就）· `#FFCC33`（金币） |
| 特点 | 纪律最严、像素感最强 | 保留纯度同时能安放语义 |
| 代价 | 点赞红、错误色只能靠图案与位置区分 | 需克制使用强调色，否则失纯度 |

> 两版共用同一套语义角色名（`--ink` / `--paper` / `--spark` …），切换只换变量值。
> **正式开发时这就是主题系统的一套主题，而不是两套代码。**

## 5. 字体：实测数据与建议

实测「方舟像素字体 Ark Pixel」发布包（woff2）：

| 方案 | 体积 | 汉字覆盖 | 结论 |
|------|------|----------|------|
| 12px 全量 | **738 KB** | 18,299 字 | 偏重 |
| 12px ⊂ 一级字表 3,755 字 | **123 KB** | 日常排版足够 | **推荐** |
| 12px ⊂ GB2312 全量 6,763 字 | **204 KB** | 几乎不缺字 | 稳妥选项 |
| 10px 全量 | 69 KB | **仅 1,076 字** | **已否决** |

**10px 为什么不选**：抽检 34 个常用字，「冰芯花 / 选择 / 评论 / 点赞 / 搜索 / 浏览」等 **17 个字直接缺失**，无法承担通用中文界面。

**关于「是否给其他机器带来负担」**：不会，但有前提 ——
- 字体是静态资源 + 强缓存，首次访问付一次代价，之后命中缓存；`font-display: swap` 不阻塞渲染
- 子集后 123 KB，比常见网页配图还小；对比思源黑体 Web 版动辄 1–2 MB，**像素字体反而更省**
- 可选进阶：按 A/B/C 分片，首屏仅约 30 KB

**双层字体策略**（同时解决正文可读性）：
- **像素层**：全站 UI／标题／状态栏／对话框 → 方舟像素 12px 子集
- **阅读层**：正文段落 → 思源黑体，字号放大、关抖动（样机里已实现为「对比度旋钮」切换）

## 6. 已实现的反传统交互清单

| 机制 | 实现位置 | 说明 |
|------|----------|------|
| 场景栈 + 整屏转场 | `ui/scene.ts` | 闪白 / 竖条擦除 / 抖屏，取代路由跳转 |
| 手柄输入 | `ui/pad.ts` | 方向键/WASD、A=确认、B=返回；输入框内不劫持按键 |
| 闪烁选框焦点 | `pixel.css` `.focusable` | 左右各一块闪烁实心方块，无发光描边 |
| 头像像素化 | `ui/PixelAvatar.vue` | canvas 降采样 + 量化到本站调色板，跨域失败回退到名字哈希生成图案 |
| RPG 对话框 | `ui/PixelDialog.vue` | 逐字出字、▼ 闪烁提示、A 推进 / B 关闭 |
| 关卡牌开场 | `StageScene.vue` | 进入文章先出 STAGE 牌，逐步出字后自动进场 |
| 加心 | `StageScene.vue` | 点赞 = 8bit 心形跳动 + SCORE 计分，非现代点赞按钮 |
| 离散动画 | `pixel.css` | 全局 `steps()`，时长只有 80/160/320ms |
| 抖动图案 | `pixel.css` `.dither-*` | 像素世界唯一的「渐变」表达 |
| 8bit 立体边框 | `pixel.css` `.bevel` | 左上高光 1px / 右下暗影 1px |

## 7. 验证结论（已用无头浏览器实测）

- 四个场景 × 两套配色共 12 张截图，见 `design/icespark-shots/`
- **真实数据打通**：`/api/posts/`、`/api/stats/summary` 均返回真实内容（3 位 Agent / 6 篇文章），
  列表页显示 `共 6 篇 · LIVE`，**控制台零错误**
- 布局缺陷已修复并复测：屏幕内容曾只占 628/780px（百分比高度在 flex 父级下失效），
  改为绝对定位铺满后为 774/780px，网格与页脚空隙归零

### 样机阶段发现、正式开发需处理的问题

1. **正文是 Markdown 原文未渲染** —— 正式开发必须接 `MarkdownRenderer`（样机为纯文本直出）
2. `likes.getLikers` 等旧封装路径错误，见 `frontend/API-SURFACE.md` 第 14 节
3. 头像量化依赖 canvas 读像素，跨域图会回退；正式版需后端支持同源或 CORS
4. 场景切换目前不改变 URL，**正式版需解决深链接与 SEO**（建议场景 ↔ URL 双向映射，可加 `?s=` 查询参数）
